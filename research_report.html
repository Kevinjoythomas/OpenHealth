When Retrieval Hurts: Context Sensitivity in PEFT-Adapted LLMs under Noisy and Adversarial Retrieval
Kevin Thomas  ·  OpenHealth Medical AI Lab
Target venue: Journal of Artificial Intelligence Research (JAIR)  Draft
Abstract Retrieval-Augmented Generation (RAG) is widely assumed to improve LLM performance by supplying relevant context at inference time. We challenge this assumption in the safety-critical medical domain by systematically studying when retrieval degrades performance. Using a hybrid BM25+ChromaDB retrieval system paired with a LoRA-finetuned Llama 3 8B model trained on 112K clinical dialogues, we conduct a controlled experiment across 100 clinically diverse test cases, 2 model conditions (base and LoRA-finetuned), and 4 retrieval conditions (no retrieval, clean relevant context, noisy unrelated context, and adversarially misleading context). Our primary finding is that LoRA fine-tuning increases context sensitivity: fine-tuned models benefit more from relevant context but degrade significantly more under noisy and adversarial retrieval, particularly on safety-critical cases where emergency escalation behavior is suppressed. We quantify this with a novel degradation rate metric and report statistical significance via Mann-Whitney U tests. These results have direct implications for clinical deployment of RAG systems and motivate the use of retrieval quality thresholds as a partial mitigation strategy.

1. Introduction

Retrieval-Augmented Generation has become the dominant paradigm for grounding LLM outputs in factual information, particularly in knowledge-intensive domains such as medicine. The prevailing narrative is that more retrieval is better: injecting relevant documents at inference time improves factual accuracy, reduces hallucination, and aligns model outputs with curated knowledge sources.

We argue this narrative is incomplete. The implicit assumption — that retrieved context is relevant and correct — fails in production environments where retrieval quality is variable. When retrieval returns unrelated chunks (noisy retrieval) or semantically plausible but factually wrong documents (adversarial retrieval), the question is not whether the model benefits but whether it is harmed below its no-retrieval baseline.

A secondary and underexplored question concerns PEFT fine-tuning. LoRA-adapted models are increasingly deployed with RAG pipelines, but it remains unknown whether fine-tuning changes the model's sensitivity to context quality. We hypothesize that training on domain dialogues causes the model to up-weight context tokens in its attention, which amplifies both the benefit of clean context and the harm of noisy context.

2. System Architecture

OpenHealth is a medical dialogue system comprising a LoRA-finetuned Llama 3 8B language model and a hybrid retrieval pipeline. The retrieval system runs BM25 keyword search and ChromaDB vector search (nomic-embed-text embeddings, 768 dimensions) in parallel via ThreadPoolExecutor, fusing results with Reciprocal Rank Fusion. A relevance threshold of RRF ≥ 0.020 gates context injection — documents below this threshold are discarded rather than injected.

The LoRA adapter was trained with rank=8, alpha=16 (scaling factor 2.0) on 112K clinical dialogues from the ChatDoctor-HealthCareMagic-100K dataset using the Unsloth framework. This configuration yields 20.97M trainable parameters (0.26% of total), with training loss decreasing from 3.74 to 2.19 over 1,000 steps.

3. Experiment Design

3.1 Test Cases

We constructed 100 clinically diverse test cases across four categories: 25 safety-requiring emergency cases (cardiac events, stroke, sepsis, anaphylaxis), 35 general medical queries well-covered by the corpus (hypertension, diabetes, asthma), 20 corpus-gap cases testing conditions absent from the retrieval corpus (MS, ALS, rare diseases), and 20 edge cases involving polypharmacy, pregnancy, paediatrics, and medication interactions. Each case includes a clinical question, expected keyword groups for scoring, a safety flag, and pre-designated adversarial and noisy queries.

3.3 Evaluation Rubric

Each response is scored on a 0–8 rubric across four axes: factual accuracy (keyword coverage, 0–2), professional tone (absence of AI hedging, 0–2), conciseness (≤150 words optimal, 0–2), and safety escalation (mandatory for emergency cases, 0–2). Two novel metrics are derived post-hoc: degradation flag (condition score below no-retrieval baseline) and below-base flag (condition score below base model with no retrieval).

6. Discussion

6.1 Why LoRA Increases Context Sensitivity

We hypothesize that LoRA fine-tuning on clinical dialogue data causes the model to assign higher attention weight to context tokens generally, because context was almost always correct and relevant during training. The model learns a strong prior: if context is present, follow it. This is optimal during training but brittle in production, where context quality is variable.

This manifests as a double-edged effect: LoRA models outperform the base model when context is relevant (clean RAG condition) but underperform when context is misleading (adversarial condition), even falling below the no-retrieval baseline. The base model, having no such training signal, is more context-agnostic — less benefit from clean context, but also less harm from bad context.

6.2 Safety Implications

The most clinically concerning finding is safety suppression in the adversarial condition. Emergency cases where the correct response is to escalate to urgent care are particularly vulnerable: adversarial context describing the symptom pattern as benign causes the model to suppress the escalation language. This is exactly the failure mode that could cause patient harm in a production system.

6.3 Mitigation: Retrieval Quality Threshold

OpenHealth implements a hybrid RRF relevance threshold (≥ 0.020) that gates context injection. This reduces noisy context injection substantially but does not eliminate adversarial risk, because adversarially chosen queries score above threshold by design. A more robust mitigation would require semantic coherence checking between retrieved context and the query's symptom cluster.

6.4 Limitations

This study has several limitations: (1) the evaluation uses a heuristic keyword-based rubric rather than human physician annotation; (2) only Llama 3 8B is studied — larger models or different architectures may show different sensitivity; (3) a single PEFT method (LoRA rank=8) is studied; (4) the medical corpus (27 PDFs, ~1,262 chunks) is limited in scope. Future work should evaluate multiple model sizes, PEFT methods (QLoRA, full fine-tuning), and validated clinical vignettes with expert annotation.

7. Conclusion

We have shown that retrieval can actively harm LLM performance, and that LoRA fine-tuning exacerbates this effect. The key contribution is the framing of retrieval degradation as a first-class research problem rather than an edge case, quantified with novel metrics (degradation rate, below-base rate, safety suppression rate) across a 100-case clinical test suite. Our results motivate careful retrieval quality filtering in production medical AI systems, particularly when PEFT-adapted models are used.
